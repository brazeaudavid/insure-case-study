One rater, three programs

Each partner program asks questions its own way. The rater only ever sees keys and codes it declared, and partners can only send what their program's contract allows. Pick a program and watch what changes and what stays fixed.

Scenario 1

Same question, different wording

The wording lives on the program version. The meaning (key, type, allowed values) lives on one immutable definition per rater version. So two partners can word a question differently and the rater reads the same key.

→
application_question · id 2003 · rater 101 employee_count integer, 1 to 5,000 · rating input
→
rater 101 receives "employee_count": 14 weighed by the headcount_factor table, whatever the wording

Scenario 2

      
The partner contract stops junk at the door

      
Each program publishes its questions as plain JSON Schema, generated from the same rows. Partners map their data to our codes once. After that, every request is checked against that schema: unknown fields, wrong types and values outside the list are rejected, and every error comes back in one response.
